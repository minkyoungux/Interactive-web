# Shampoo · Experiment 14

## 프로젝트 연결

Vite + TypeScript 멀티 페이지 프로젝트다. `src/hub.ts`가 해시로 예제를 선택하고 iframe의 URL을 변경한다. Shampoo는 `/shampoo.html` 또는 `/#shampoo`에서 실행한다. `vite.config.ts`에 별도 빌드 진입점을 추가했다.

기존 카메라 예제의 전체 화면, 상단 제목/상태, 하단 조작/안내 배치를 사용한다. Shampoo는 옅은 청록색과 흰 거품으로 구분한다. 기존 `capture.ts`를 사용해 사진과 영상을 촬영한다. 카메라 video와 거품 canvas가 같은 좌우 반전 cover 변환을 사용한다. 유리의 김 효과는 별도 Canvas 레이어로 올려 촬영에도 함께 합성한다.

기존 예제의 추론/렌더링 코드는 변경하지 않았다. 허브는 iframe 교체 직전에 outgoing window에 `interactive:dispose` 이벤트를 동기적으로 전달한다. Shampoo는 이 이벤트와 `pagehide`, `beforeunload`, HMR 정리를 처리한다.

## 파일

- `src/shampoo.ts`: 화면, 카메라 생명주기, Worker 스케줄링, 랜드마크 부착, 캐시 스프라이트 렌더링.
- `src/shampoo-worker.ts`: 역할별 Worker. 손 Worker는 HandLandmarker, human Worker는 FaceLandmarker와 ImageSegmenter를 소유한다.
- `src/shampoo-tracking.ts`: 양쪽 Worker 메시지 타입.
- `src/shampoo-geometry.ts`: 실제 마스크의 연결 영역, 경계 방향, 얼굴 기준 좌표, 부착 좌표, 제스처 및 스트로크 상태.
- `src/shampoo.css`: 반응형 화면.
- `src/shampoo-sprites.ts`: 작은 반투명 머리 거품, 투명한 무지개빛 비눗방울, 러버덕/먹기 모션의 Canvas 스프라이트 캐시.
- `src/shampoo-bath.ts`: 비눗방울 중력·충돌·쌓임과 러버덕의 방문·이동·섭취.
- `src/shampoo-fog.ts`: 김 낀 유리, 손 경로의 부드러운 지우개 마스크, 부분 선명화.
- `public/shampoo/`: 고정 버전 SelfieSegmenter 모델과 설치된 MediaPipe 1.0.1의 module Worker용 WASM. 기존 얼굴/손 모델은 `public/lemonade/mediapipe/`를 재사용한다.

## HumanSeg와 기본 거품

모델 메타데이터의 실제 라벨은 `selfie` 하나다. `getLabels()`로 채널을 찾아 `confidenceMasks[selfieIndex].getAsFloat32Array()`를 읽는다. 문서의 일반적인 background/person 인덱스를 이 모델에 하드코딩하지 않는다. confidence mask는 콜백 내부에서 복사하고 원본은 MediaPipe가 회수한다.

confidence 0.62 이상이며 얼굴의 이마 선 위에 있는 마스크 픽셀 중 이마에 연결된 영역을 추출한다. 이마 선은 얼굴 상단 랜드마크로 잡지만 실루엣 자체를 랜드마크로 만들어 내지 않는다. 마스크가 없거나 유효하지 않으면 기본 거품을 생성하지 않는다. 넓거나 높은 머리도 실제 연결 영역에 따라 샘플링 범위를 확장한다. 외곽선/랜드마크/디버그 경계는 화면에 그리지 않는다.

기본 거품은 작고 촘촘한 청록·회청색 샴푸 거품으로 실루엣 전체를 겹쳐 채운다. 기본 거품 크기는 최초 구현의 약 절반이며, 흰색을 넓게 채우던 gradient는 은은한 색으로 바꿨다. 샴푸 스프라이트는 여러 작은 셀이 겹친 크림 같은 덩어리이며, 기본 머리 거품은 낮은 불투명도로 표시한다. 가장자리 스프라이트는 마스크에 잘라 넣지 않아 경계를 조금 넘는다. 각 거품에 가까운 실제 confidence 경계의 gradient 방향을 구하고 법선/접선 방향으로 작게 진동시킨다. `prefers-reduced-motion`에서는 진동과 생성 팽창을 생략한다.

## 손동작과 부착

- 검지: 검지만 펴고 다른 손가락을 접으면 실제 검지 끝(랜드마크 8)을 따라 작은 샴푸 거품을 만든다. 검지를 편 채 다른 세 손가락을 접은 손을 주먹으로 오인하지 않도록 검지 동작을 먼저 구분한다. 3차원 관절의 방향·길이를 판별해 카메라 쪽으로 검지를 내밀어도 인식한다.
- Pinch: 엄지·검지 간격을 손 크기로 정규화하고 진입/이탈 기준을 달리한다. 얼굴/두피에서 시작하면 손 경로를 촘촘하게 보간해 작은 거품을 계속 생성한다.
- 주먹: 손가락이 손바닥 쪽으로 접힌 정도를 판별한다. 얼굴/두피에서 시작하면 넓은 방사형으로 큰 샴푸 거품 19개를 생성한다. 각 거품 반지름은 얼굴 반폭의 0.15~0.26이며, 검지/Pinch의 0.018~0.033보다 확실하게 크다. 정지 중에도 410ms 간격으로 생성하며, 움직이면 군집 사이를 보간한다. 접촉 판정은 시작할 때 적용하므로 얼굴 밖에서도 손을 펼 때까지 이어진다.
- open/검지/Pinch/fist 전환 시 스트로크 상태를 초기화해 다시 진입할 수 있다. 손 결과의 배열 순서 대신 이전 위치로 두 손을 대응한다.
- 샴푸 거품은 가까운 얼굴 랜드마크 4개의 가중치와 얼굴 기준 offset을 저장한다. 매 프레임 현재 랜드마크로 위치를 복원해 이동·회전·크기 변화와 국소 표정 변화를 따라간다. 자동 수명 만료는 없다. 명시적 씻어내기와 카메라 세션 종료 때 초기화한다. 러버덕이 닿으면 해당 거품을 먹어 없앤다.
- 장시간 사용 시 메모리를 제한하기 위해 영구 거품은 12,000개까지 유지한다. 기존 거품을 지우지 않고, 한도에 도달하면 씻어내기 안내와 함께 추가 생성을 멈춘다.

## O 사인으로 비눗방울 불기

엄지·검지 끝을 만나게 하고 검지를 둥글게 굽혀 O/OK 사인을 만든다. 나머지 손가락 중 두 개 이상을 펴고, 고리를 입 가까이 가져가면 약 95ms마다 비눗방울이 나온다. 입과 고리 간 거리는 얼굴·손 크기로 정규화한다. 직선 검지/Pinch와 주먹은 구분한다. O 사인의 고리·곡률도 손의 깊이 좌표를 포함해 판별하고, 검지를 곧게 편 손은 O로 인정하지 않는다. O 사인이 인식되는 동안에는 붙이는 Pinch 거품을 만들지 않는다. 실제 호흡 소리나 마이크는 사용하지 않는다.

입 앞 O 사인만 떠다니는 비눗방울을 만든다. O 이외의 검지/Pinch/주먹은 얼굴에 붙는 샴푸 거품을 만든다. 비눗방울은 6종의 구형 박막 반사·무지개빛 얇은 테두리·하이라이트를 캐시하고, 중심은 거의 투명하게 둔다. 크림 같은 샴푸 거품과 스프라이트를 공유하지 않는다. 반지름 18~84 CSS 픽셀(지름 36~168px) 범위에서 크게 다양한 크기로 나온다. 얼굴 크기와 화면 너비를 기준으로 크기를 정하며, 최초 O 사인 구현보다 약 5~6배 커졌다. 큰 방울이 충돌 검사에서 빠지지 않도록 공간 버킷은 현재 가장 큰 방울의 지름에 맞춘다. 고리에서 잠깐 위로 떠오른 뒤 약한 중력으로 내려온다. 화면 좌우·바닥과 다른 비눗방울에 부드럽게 충돌하고 바닥에 쌓인다. 공중에 나온 비눗방울은 얼굴에서 독립적인 화면 좌표로 움직이므로 얼굴을 잃어도 계속 떨어진다.

충돌은 1/60초 고정 간격과 공간 버킷으로 계산하며, 비눗방울은 최대 420개를 유지한다. 가득 차면 기존 쌓임을 보존하고 추가 생성만 멈춘다. 러버덕이 먹어 공간이 생기면 다시 생성할 수 있다. O 사인의 순간적인 손 누락은 기존 220ms grace를 적용하지만 명시적인 다른 손동작으로 바뀌면 바로 멈춘다.

## 거품 먹는 러버덕

카메라의 활성 시간이 약 10초가 되면 러버덕이 옆에서 들어온다. 약 12초 동안 가까운 거품/비눗방울을 찾아 둥실거리며 돌아다니고, 부리 가까이에 닿으면 먹으며 입을 움직인다. 나간 뒤 약 9초 후 다시 방문한다. 화면을 숨긴 동안에는 방문 시간과 물리 동작도 정지한다.

붙인 Pinch/주먹 거품, 바닥이나 공중의 비눗방울, 기본 머리 거품을 모두 먹는다. 기본 거품은 얼굴 기준의 먹은 영역을 기록해 HumanSeg가 갱신되어도 바로 재생성하지 않는다. `거품 씻어내기`는 비눗방울·러버덕·먹은 영역·붙인 거품을 초기화하고 기본 머리 거품을 다시 표시한다.

## 왼손으로 김 닦기

카메라를 켜면 영상과 거품 위에 얇은 김 낀 유리가 표시된다. **실제 왼손을 펴고 쓸면** 손바닥이 지나간 부분의 유리 마스크가 지워져 원래 영상과 거품이 선명하게 보인다. 손바닥 크기에 맞춰 약 42~105 CSS 픽셀 반지름의 부드러운 경로를 보간한다. 느린 손 움직임도 누적해서 인식한다. 오른손, 가만히 둔 손, 주먹/검지/Pinch/O 사인은 유리를 닦지 않는다.

얼굴 검출 없이도 닦을 수 있다. 손의 짧은 누락에는 220ms grace를 적용하며 긴 누락이나 큰 좌표 점프는 경로를 새로 시작해 화면 중간이 갑자기 지워지는 일을 막는다. 닦은 자리는 유지하고, 화면 크기를 변경해도 같은 상대 위치에 보존한다. `김 다시 끼기` 또는 새 카메라 세션으로 유리를 초기화한다. 거품 씻어내기와는 별개다.

Worker가 HandLandmarker의 handedness와 confidence를 전달한다. 추론 입력은 CSS 반전 전의 실제 카메라 프레임이므로, [MediaPipe의 좌우 판정 규약](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/hands.md#multi_handedness)에 따라 라벨을 반대로 정규화하여 실제 왼손/오른손을 구분한다. 손 슬롯 대응은 기존처럼 이전 위치를 사용한다.

김 레이어는 긴 변 900px 이하로 제한해 약 85ms마다 영상·거품을 흐리게 합성한다. 미세한 응결 텍스처와 가장자리가 부드러운 지우개 스프라이트는 재사용한다. 손이 닦는 동안에는 다음 프레임에 즉시 마스크를 갱신한다. 닦인 영역은 이 레이어가 투명해져 원본 video/scene의 전체 해상도가 그대로 드러난다. 숨김/종료 때 기존 RAF 중단과 함께 갱신을 멈춘다. 촬영은 기존 공통 capture가 video → scene → fog 순서로 합성한다.

## 성능과 생명주기

표시용 카메라는 1920×1080 해상도를 요청하며 기기에서 지원하는 해상도를 사용한다. 화면을 채우는 cover 확대 때문에 낮은 해상도의 원본이 흐릿해지는 것을 줄인다. 추론용 프레임만 긴 변 512px로 축소하며, 표시용 video에는 흐림 필터나 저해상도 Canvas 복사를 적용하지 않는다.

손과 human 추론은 별도 Worker에서 실행한다. 각 Worker에 전송 중인 프레임은 1개로 제한하고 전달한 ImageBitmap은 추론 후 닫는다. 손 추론은 기본 45ms, 제스처 중 32ms 목표 간격으로 우선 요청한다. 얼굴은 60/75ms, HumanSeg는 기본 190ms에서 제스처 중 580ms로 갱신 빈도를 낮춘다. 이는 목표 스케줄이며 실제 처리율은 기기에 따라 다르다.

메인 화면은 requestAnimationFrame으로 렌더링한다. 거품의 gradient/하이라이트는 시작 시 머리 거품 4개, 비눗방울 6개, 러버덕 2개의 Canvas 스프라이트로 캐시하며 매 프레임 다시 만들지 않는다. 렌더링 해상도는 약 300만 픽셀로 제한한다.

손 누락에는 220ms, 얼굴에는 360ms grace를 적용한다. HumanSeg는 낮춘 갱신 주기를 포함해 마지막 유효 마스크를 최대 1초 유지한다. 기한을 넘으면 표시하거나 스트로크를 연결하지 않는다. 얼굴 재검출 시 기존 영구 거품은 복원하고 기본 거품은 새로운 마스크를 기다린다.

숨김 상태에서는 RAF·추론 요청을 중단하고 비디오 트랙을 비활성화한다. 다시 표시되면 얼굴/마스크를 갱신한다. 종료할 때 RAF 취소, 트랙 stop, video.srcObject 해제, Worker에 graph close 요청 후 종료한다. 초기화가 멈춘 Worker도 300ms 뒤 강제 종료한다. 세션 generation으로 늦게 도착한 권한 응답·ImageBitmap·추론 응답을 무효화하며 늦게 열린 스트림도 즉시 stop한다.

MediaPipe 1.0.1은 그래프 생성 후 전역 ModuleFactory를 지운다. module import는 캐시되므로 human Worker에서 두 번째 그래프를 만들기 전에 로더의 default export를 다시 설정한다. 기존 예제의 런타임 파일은 수정하지 않는다.

## 검증

```sh
npm run build
node --test tests/shampoo.test.mjs tests/shampoo-bath.test.mjs tests/rubber-human.test.mjs
npm run dev -- --host 127.0.0.1
SHAMPOO_BROWSER_URL=http://127.0.0.1:5173 node tests/shampoo-browser.cjs
```

브라우저 검사는 Playwright와 Chrome을 사용한다. 별도 환경에서는 `PLAYWRIGHT_MODULE`, `SHAMPOO_CHROME_EXECUTABLE`, `SHAMPOO_BROWSER_URL`을 지정한다. `SHAMPOO_PORTRAIT=/absolute/path/portrait.jpg`를 지정하면 실제 세 모델의 Worker 초기화에 더해 얼굴 사진에서 실제 FaceLandmarker + HumanSeg 결과로 거품이 그려지는지 검사한다. 테스트에서 사용한 사진은 프로젝트에 포함하지 않았다.

기하/상태 검사는 얼굴 이동·회전·크기·국소 표정 추종, 비정상/빈 마스크, 연결 성분, 주먹 반복 주기, 경로 보간, 제스처 전환, grace를 검증한다. 브라우저 검사는 실제 WASM 모델 실행과 별개로 합성 랜드마크를 주입해 마스크 대기/만료, 영구 Pinch, 주먹 반복/얼굴 밖 경로, 누락/재검출, 화면 숨김/복귀, 카메라 종료, 허브 전환을 검증한다. 검지 동작과 주먹의 분리, 검지 끝의 부착 위치, 작은 검지/큰 주먹 샴푸 거품의 크기 차이, 카메라 방향을 향하는 검지, O 사인의 근접·곡률·손가락 조건, 재진입/해제, 크고 다양한 투명 비눗방울, 중력·바닥 쌓임, 러버덕의 비눗방울/머리 거품 섭취도 검증한다. 왼손만 닦기, 손 정지/느린 이동/누락 후 재진입, 얼굴이 없어도 닦기, 화면 크기 변경 시 닦인 영역 유지, 다시 김 끼우기 및 종료도 검증한다. 데스크톱/모바일과 불기·쌓임·러버덕 섭취·왼손 닦기 화면도 저장한다.

실제 사용자의 웹캠과 다양한 조명/손 방향에서의 인식률은 자동 테스트로 대체하지 않았다. 브라우저 카메라는 HTTPS 또는 localhost에서 실행한다.
