# DoodleFace · 로컬 2인 얼굴 낙서

## 프로젝트 분석과 통합

이 프로젝트는 Vite 6 / TypeScript 멀티 페이지 앱이다. `index.html`의 `src/hub.ts`는 예제 배열을 상단 탭으로 만들고 해시 라우팅으로 iframe을 교체한다. 기존 예제는 각각 HTML, TypeScript, CSS 진입점을 소유한다. `vite.config.ts`에 등록된 HTML 전체를 `npm run build`로 빌드한다.

기존 DoodleFace HTML·스타일·구현은 없었다. 따라서 종이 질감 배경, 세리프 타이포그래피, HUD, 두 패널, 동일한 10색 팔레트와 얼굴 SVG 그래픽을 새 예제 전용 파일에 구현했다. 기존 예제의 CSS, HTML 진입점, 카메라 설정은 변경하지 않았다. 허브에는 `doodleface` 탭과 경로만 추가했다. 허브가 이미 전송하던 `interactive:dispose` 이벤트를 받아 iframe 교체 직전에 동기적으로 자원을 정리한다.

실행: `npm run dev` 후 `http://localhost:5173/#doodleface` 또는 `/doodleface.html`.

## 게임 방법

1. 두 사람이 카메라 앞에 나란히 앉고 `2인 게임 시작 ＋`를 누른다.
2. 거울 영상 왼쪽 사람은 PLAYER 1, 오른쪽 사람은 PLAYER 2다. 양쪽 얼굴이 약 650ms 안정적으로 감지되면 5초를 센다. 준비 중 얼굴을 잃으면 다시 기다린다.
3. 화면이 850ms 동안 반대편으로 미끄러져 교환된다. 데스크톱은 수평, 600px 이하 세로형 레이아웃은 수직 이동한다. 세로형 모바일의 플레이 화면은 두 패널이 스크롤 없이 한 화면에 들어오도록 배치한다.
4. 왼쪽에는 PLAYER 2의 얼굴이 있고 PLAYER 1의 손이 그린다. 오른쪽에는 PLAYER 1의 얼굴이 있고 PLAYER 2의 손이 그린다. 가운데 경계를 넘지 않고 각자 손 하나를 사용한다.
5. 엄지·검지 끝의 중간이 연필 끝이다. 상대 얼굴 안에서 두 손가락을 맞대면 새 획을 시작한다. 시작한 획은 얼굴 밖에서도 이어지고 손가락을 벌리면 끝난다.
6. 각 패널 위의 색을 클릭하거나 색 위에서 핀치해 해당 펜 색을 선택한다.
7. 교환 애니메이션이 실제로 끝난 뒤 정확히 60초 동안 그린다. 종료 안내 `완성된 얼굴을 보여주세요`를 2.4초 보여주고, 안내 없이 교환된 결과를 10초 더 보여준다. 이후 카메라와 인식 모델을 정리하고 로비로 돌아간다.

## 구현 파일과 좌표

- `src/doodleface.ts`: 화면, 단일 카메라, 모델 생성, 추론 스케줄, 캔버스 렌더링, 스냅샷 슬라이드, 수명 관리.
- `src/doodleface-core.ts`: 좌표 변환, 얼굴 포즈·예측, 랜드마크 앵커, 핀치 히스테리시스, 획과 게임 시간 규칙.
- `src/doodleface.css`: 전용 디자인과 반응형 레이아웃. 외부 폰트를 요청하지 않는다.
- `doodleface.html`: Vite 진입점. `connect-src 'self'` 정책으로 MediaPipe 런타임의 외부 통계 전송도 차단한다. 이 정책은 다른 예제에는 적용하지 않는다.

카메라는 게임 시작마다 `getUserMedia`를 한 번만 호출하며 `audio:false`, `facingMode:'user'`를 요청한다. 한 영상 원본의 좌우 절반을 정확히 별도 source rectangle으로 잘라 각 패널에 독립적으로 cover + 거울 모드로 그린다. 얼굴이 없어도 영상은 계속 보이고, 작은 반투명 WAITING 배지만 표시한다.

얼굴 외곽 중심과 손바닥 중심을 원본 좌표에서 구하고 거울 좌표 `x = 1 - raw.x`로 배정한다. `x < .5`는 PLAYER 1, 그 외는 PLAYER 2다. 소유자를 바꿔 결과 배열 순서를 따르거나 handedness로 배정하지 않는다. 각 점은 `local.x = mirrored.x * 2 - side`, `local.y = raw.y`로 자기 절반의 좌표로 변환한다. 픽셀 투영은 카메라와 같은 cover 변환을 사용한다.

낙서 점은 대상 얼굴에서 가장 가까운 랜드마크 번호, 얼굴 크기로 정규화하고 회전 보정한 오프셋을 저장한다. 다음 얼굴 포즈로 복원하면 이동·확대·회전과 해당 랜드마크의 표정을 따른다. 마지막 두 포즈를 이용해 최대 45ms, 변위 상한 .025의 짧은 예측을 적용한다. 오래된 포즈는 예측하지 않는다. 새 점을 예측 포즈에 붙이고 같은 추론 프레임에 바로 그린다.

핀치 비율은 엄지·검지 끝 거리 / 검지·새끼손가락 뿌리 사이 손바닥 폭이다. 카메라 종횡비로 보정한다. 시작 임계값은 .62, 해제 임계값은 .82다. 열린 상태가 110ms 안정적으로 유지돼야 놓기를 확정하고, 미인식은 안정 해제 시간에 포함하지 않는다. 손이 사라져도 220ms까지 마지막 펜과 핀치를 유지한다.

## 모델과 성능

`public/mediapipe`에는 기존 로컬 얼굴·손 모델을 복사하고, 설치된 `@mediapipe/tasks-vision` 1.0.1과 일치하는 WASM 런타임을 배치했다. FaceLandmarker 한 개는 `numFaces:2`, HandLandmarker 한 개는 `numHands:2`다. GPU 초기화 실패 시 실패한 객체를 닫고 CPU로 재시도한다. 모델 초기화 중 생성된 객체도 별도 소유 목록에 즉시 등록해 이탈 시 정리한다.

프레임당 추론은 하나만 수행한다. 얼굴 추론 사이에 손 추론을 배정하고, 핀치 중 손 간격은 32ms(저사양 50ms), 얼굴 간격은 100ms(저사양 150ms)로 조정한다. 실제 빈도는 카메라 새 프레임 도착과 장치 추론 시간에 따라 달라진다. 대기·카운트다운에서도 손 모델을 실행하고 결과 감상 중에는 얼굴만 실행한다.

논리 코어 수 4 이하 또는 보고된 메모리 4GB 이하이면 저사양 모드를 사용한다. 평균 추론 시간이 24ms를 넘으면 실행 중에도 낮춘다.

| 설정 | 일반 | 저사양 |
| --- | --- | --- |
| 요청 카메라 해상도 | 1280×720 | 960×540 |
| 요청 카메라 fps 상한 | 30 | 24 |
| 추론 입력 폭 | 640 | 480 |
| canvas DPR 상한 | 1.75 | 1 |
| 렌더 빈도 상한 | 60fps | 24fps |

각 렌더 프레임에 패널·팔레트 크기를 한 번 읽고 변환을 재사용한다. 점 추가나 앵커 복원 루프에서 `getBoundingClientRect`를 호출하지 않는다. 게임 종료, 수동 종료, 허브 탭 변경, pagehide, HMR 시 트랙·모델·rAF·슬라이드 애니메이션·스냅샷·낙서 상태를 정리한다. 이탈 뒤 늦게 해결되는 카메라 또는 모델 생성도 즉시 정리한다. 카메라 거절·비보안 문맥·모델 오류는 짧은 한국어 메시지와 재시작 버튼으로 처리한다.

방 서버, 네트워크 플레이, WebRTC, WebSocket, SSE, 관련 환경변수는 없다. 영상과 랜드마크는 기기 밖으로 전송하지 않는다.

## 검증

```sh
npm test
npm run build
npm run test:doodleface:browser
# 다른 로컬 포트나 production preview로 검증:
node tests/doodleface-browser.cjs http://127.0.0.1:5178
```

브라우저 테스트는 설치된 Playwright 또는 이 작업 환경의 기존 Playwright를 사용한다. macOS에서는 설치된 Google Chrome을 headless로 실행한다. 다른 환경에서는 Playwright Chromium 설치가 필요하다.

단위 테스트는 좌우 경계, cover, 랜드마크 부착의 이동·회전·크기·표정, 짧은 예측, 핀치 시작·해제·가림, 얼굴 안에서만 획 시작, 안정 감지, 교환 이후 60초와 결과 시간을 검증한다. 기존 예제의 단위 테스트도 함께 실행한다.

브라우저 테스트는 가상 카메라·합성 랜드마크로 데스크톱/모바일 슬라이드의 중간 위치, 교환 전후 원본 표본 픽셀, 양쪽 플레이어 낙서, 클릭·핀치 색 선택, 프레임당 단일 추론, 종료/이탈/늦은 초기화 정리, 오류와 CPU 재시도를 검증한다. 가속 시간은 테스트 문맥에서만 주입하며 실제 슬라이드는 850ms로 실행한다. 별도 문맥에서는 실제 로컬 WASM과 두 모델을 초기화하고 실제 추론, 미인식 영상 유지와 정리를 확인한다. 외부 HTTP 요청과 pageerror가 없는지도 검사한다.

스크린샷은 `artifacts/doodleface/`에 남긴다. 실제 두 사람의 카메라 영상과 조명·가림에 따른 제스처 품질은 자동 테스트 범위 밖이며, 실제 사람으로 플레이했다고 주장하지 않는다.

실행 결과: 단위 테스트 36개 통과, TypeScript 검사 및 전체 멀티 페이지 production 빌드 통과. 개발 서버와 Chrome production preview 브라우저 테스트의 모든 시나리오가 통과했고 DoodleFace 외부 HTTP 요청과 pageerror는 0개였다. 일반/저사양 렌더 설정, 세로형 모바일의 두 패널 화면 내 배치, 양쪽 펜의 낙서와 초기화 중·슬라이드 중 이탈도 검증했다. 기존 Three.js 번들의 크기 안내는 빌드를 실패시키지 않는다.
