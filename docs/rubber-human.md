# 고무 인간 · 프로젝트 구조와 새 예제

## 프로젝트 구조

- Vite 6 + TypeScript의 멀티 페이지 앱. `vite.config.ts`에 각 HTML을 빌드 진입점으로 등록한다.
- `index.html` → `src/hub.ts` / `hub.css`: 해시로 예제를 선택하고 iframe에서 실행한다. 새 예제는 배열과 Vite 진입점에 함께 추가한다.
- 예제별 `*.html` → `src/<name>.ts` / `.css`: 화면, 상태, 애니메이션을 각각 소유한다.
- Anyma는 `public/assets`의 기존 번들을 직접 로딩한다. 타닥타닥 냥이는 `game.html` → `src/main.ts`다.
- Sampler는 Three.js와 Web Audio, Claw는 Three.js와 Cannon, 나머지 손 추적 예제들은 Canvas 또는 Three.js를 사용한다.
- Lemonade는 얼굴·손 추적, WaterTouch / Balloon / 공중 도예 / ASMR / Type Vessel은 손 추적을 사용한다.
- `public/lemonade/mediapipe/`에 손·얼굴 모델과 WASM 런타임이 이미 있어 새 외부 다운로드 의존성 없이 재사용한다.
- `src/capture.ts` / `capture.css`: 공통 사진·동영상 촬영. `interactivecaptureprepare` 이벤트 직후 화면의 video/canvas를 합성한다.
- `practice/`는 마음절, `personal-practice/`와 그 하위 `prism/`은 별도의 실습 페이지다.
- `npm run build`는 `src/` TypeScript 검사 후 모든 진입점을 `dist/`로 빌드한다. `practice/`의 TypeScript는 현재 tsconfig 검사 범위 밖이다.

## 실행과 조작

`npm run dev` → `/#rubber-human` 또는 `/rubber-human.html`.

1. 카메라를 켜고 잠시 손을 내려 깨끗한 얼굴 텍스처를 준비한다.
2. 화면에서 얼굴과 겹치는 위치에 엄지·검지를 맞댄다.
3. 집은 채 움직이면 잡힌 얼굴 지점이 따라간다. 벌리면 탄성으로 돌아온다.
4. 마우스·터치 드래그도 지원한다. 카메라 없이 표시되는 얼굴로 먼저 체험할 수 있다.
5. `다시 말랑하게` 또는 Escape로 변형을 초기화한다. 카메라 끄기와 페이지 이탈 시 스트림을 정리한다.

현재 한 얼굴과 한 손을 추적한다. 핀치는 얼굴 위에서 새로 시작해야 하며, 복귀가 거의 끝난 뒤 다시 잡을 수 있다. 카메라는 localhost 또는 HTTPS와 브라우저 권한이 필요하다.

## 구현

- `src/rubber-human.ts`: 카메라, 얼굴 기준 좌표, 손 핀치 상태, 피부색 마스크, 화면과 자원 수명 관리.
- `src/rubber-human-renderer.ts`: 160 × 160 분할 표면과 GPU 셰이더. 움직이는 가우시안 변형장을 64단계로 적분해 잡은 점은 손끝에 붙이고 주변은 곡선으로 늘린다.
- `src/rubber-human-physics.ts`: 동일한 변형장의 CPU 계산, 좌표 변환, 히트 테스트, 프레임률과 독립적인 감쇠 스프링.
- 피부색은 양 볼의 205·425 랜드마크 주변 5 × 5 픽셀 중앙값으로 추출한다. 원래 얼굴 외곽 전체를 불투명한 피부색 그라데이션으로 덮고, 그 위에 늘어나는 텍스처를 그린다.
- 손이 얼굴에 가까워지면 마지막 깨끗한 텍스처를 보존해 손가락까지 얼굴에 복사되는 현상을 줄인다. 손이 멀어지고 복귀가 끝나면 갱신한다.
- 피부색 덮개는 얼굴 내부의 이목구비만 가리고 실제 얼굴 가장자리의 명암은 보존한다. 블러·경계 그림자·얼굴 전체의 균일한 피부색 테두리를 사용하지 않는다. 텍스처 바깥쪽은 바로 안쪽의 원래 피부를 확장해 국소 명암을 유지하며 외곽은 기본 안티앨리어싱만 사용한다. 정지 상태는 얼굴 누끼를 재합성하지 않고 실시간 영상 자체를 사용한다. 체험용 얼굴에는 격자선과 별도 피부색 덮개를 그리지 않는다. 머리의 위치·크기·회전은 현재 랜드마크를 따른다.
- 얼굴과 손 추적은 같은 미러링·cover 좌표 변환을 사용한다. 최종 영상은 하나의 2D 캔버스에 합성되어 공통 촬영 기능에 포함된다.
- 당긴 지점에 부드러운 붉은 기, 방사형 부풀림, 밝은 윗면과 어두운 아랫면을 적용해 만화 같은 혹을 표현한다. 당기는 힘에 비례해 커지고 해제 후에는 천천히 사라진다.
- 얼굴 외곽선은 따로 그리지 않는다. 핀치 히트 테스트는 얼굴 안쪽만 허용하며, 얼굴 텍스처만 변형하고 카메라 배경은 그대로 유지한다.
- 당기기를 놓고 스프링 복귀가 안정되면 해당 얼굴 좌표에 밴드가 붙는다. 밴드는 얼굴 이동·회전과 이후 변형을 따르며, 최대 8개를 유지한다. 같은 위치를 다시 당기면 밴드를 갱신한다. 초기화하면 모두 지운다.
- GPU 추적 초기화 실패 시 CPU로 재시도한다. 손·얼굴 추적 상실 및 포커스 이탈 시 잡기를 해제한다.

## 검증

- `npm run build`
- `node --test tests/rubber-human.test.mjs`: 핀치 위치 일치, 긴 변형의 표면 뒤집힘 방지, 좌표 변환, 프레임률 독립 복귀, 동작 줄이기, 얼굴 밖 히트 테스트.
- Chrome에서 데스크톱·모바일 화면, 마우스 드래그, 탭 진입을 확인했다.
- 가상 카메라로 실제 MediaPipe 모델 로딩을 확인하고, 합성 랜드마크로 핀치·이동·해제·얼굴 추적 상실·카메라 정리를 검증했다.
- 실제 사람의 카메라 제스처는 자동 검증하지 않았다. 조명, 손의 가림, 고개 각도에 따른 추적 품질은 실제 카메라에서 확인해야 한다.

추가 검증: 명암이 있는 가상 얼굴에서 정지 상태의 표본 픽셀 4개가 원본 영상과 일치하는지, 당기는 중 얼굴 밖 표본 픽셀 4개에 피부색 덮개·블러가 번지지 않는지 확인했다. 당김 및 복귀 후 밴드 화면도 육안 확인했다. 실제 사용자의 카메라 화면은 컴퓨터 화면 접근 권한이 없어 확인하지 못했다.

## 성능 최적화

비주얼을 유지하기 위해 얼굴 텍스처 768 × 768, 메시 160 × 160, 변형 적분 64단계, 카메라 해상도·DPR·추적 빈도와 물리 상수는 변경하지 않았다. 의존성을 추가하거나 그래픽 품질을 낮추지 않았다.

- 텍스처 갱신의 작업 캔버스 네 개를 필요할 때 한 번 만들고 재사용한다. 카메라를 끄면 버퍼를 해제한다.
- 두 번 투영하던 카메라 영상은 한 번 투영해 재사용하고, 외곽이 같으면 마스크도 다시 만들지 않는다.
- 얼굴의 전체 478개 랜드마크 대신 실제 사용하는 좌표만 투영한다.
- 배경의 점과 그림자 경로를 화면 크기가 바뀔 때만 만든다.
- 같은 화면은 다시 그리지 않고, 같은 GPU 입력은 기존 렌더링 결과를 재사용한다. GPU의 보관 버퍼는 재합성·촬영 때에도 결과가 남도록 설정한다.
- 카메라를 끈 정지 상태의 애니메이션 루프는 멈춘다. 화면 숨김 시 추적·렌더링·영상 트랙을 일시 중지하고 돌아오면 재개한다.

검증 결과:

- 모바일 390 × 844 / DPR 1과 데스크톱 960 × 640 / DPR 2에서 정지·당김·긴 당김·대각선 당김·밴드가 붙은 복귀·체험 얼굴의 12개 화면을 비교했고, 변경 전후 픽셀이 모두 일치했다.
- 이미 그린 동일한 상태를 12번 요청했을 때 추가 GPU 렌더링 12회 → 0회.
- 작업 캔버스를 준비한 뒤 텍스처 갱신 5회에서 임시 캔버스 생성 15개 → 0개.
- 핀치, 복귀, 밴드, 정지 시 루프 중단, 숨김 시 중단과 복귀, PNG 사진과 MP4 영상 저장을 브라우저에서 검증했다.
- 위 수치는 재사용과 화면 보존 검증 결과이며, 실제 기기의 온도를 측정한 결과는 아니다.

회귀 검증: `npm run build`, `node --test tests/rubber-human.test.mjs`. 개발 서버를 켠 뒤 `node tests/rubber-human-browser.cjs`로 브라우저 검증도 실행할 수 있다. 브라우저 검증에는 Playwright가 필요하며, Codex에 포함된 런타임을 자동 탐색한다. 별도 설치를 사용하면 `PLAYWRIGHT_MODULE`, `RUBBER_CHROME_EXECUTABLE`, `RUBBER_BROWSER_URL`로 경로와 주소를 지정할 수 있다. 테스트 카메라는 합성 영상이며 실제 카메라를 사용하지 않는다.
